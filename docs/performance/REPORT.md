# تقرير تحسين أداء الهاتف — 2026-11-17

## النتيجة والنطاق

نُفّذت إصلاحات الواجهة العامة فقط. لا تعديل على API أو لوحة الإدارة أو قواعد الموافقة والتسويق أو إرسال عروض الأسعار أو `revalidate=300` أو سياسة canonical/hreflang.

الاختبارات الوظيفية والبناء والظهور من SSR نجحت. **هدف الهاتف ≥90 وLCP ≤2.5 ثانية لم يتحققا في المحاكاة المحلية الحالية.** يلزم قياس النشر الجديد؛ لا يوجد ضمان 95. هذه مقارنة بين الإنتاج القديم ونسخة production build محلية تستخدم API الحقيقي، وليست مقارنة إنتاج قبل/بعد بنفس الشبكة. لا تتوفر قياسات INP ميدانية جديدة أو جهاز Android فعلي أو نقطة اختبار يمنية/خليجية مضبوطة.

## التغييرات

- إزالة Preloader والانتقال العام الذي يخفي الصفحة. كشف الاختبار حاجزًا إضافيًا في `app/[locale]/loading.tsx` يبقي المحتوى مخفيًا بلا JavaScript؛ أُزيل أيضًا.
- H1 وHero وCTA مرئية في HTML الأولي. Reveal وparallax أصبحا زخرفة CSS تدريجية على الكمبيوتر؛ المحتوى لا يبدأ بشفافية صفرية.
- LandingPage أصبح Server Component، مع جزر مستقلة لـHero والتوزيع والفروع، وchunk مستقل للخريطة مع حفظ HTML والفهرسة.
- إزالة Framer Motion بعد قياس حزمته بنحو 42 KiB مضغوطة. التفاعل باقٍ عبر CSS وIntersectionObserver. التبديل الآلي يتوقف خارج الشاشة والتبويب المخفي وعند التركيز/المرور وعلى الهاتف ومع reduced motion؛ التبديل اليدوي باقٍ. إشارات الخريطة تعمل على الكمبيوتر عند ظهورها فقط.
- Alexandria متغيّر WOFF2، أوزان 400–800، preload واحد و`display: swap`. المصدر والترخيص والتحويل في [توثيق الخط](../../public/fonts/README.md).
- ضغط الزخرفة والشعارين إلى WebP وتحسين SVG. المقارنة البصرية للخريطة سليمة؛ متوسط فرق قنوات raster عند 800×600 يساوي 0.0092 من 255. الأصل والإحداثيات محفوظان.
- `sizes` صريحة للصور المرنة. صورة العرض على الهاتف أسفل النسخة الأساسية وتُحمّل lazy. مصادر الصور الخارجية و`MEDIA_HOST` محفوظة.
- تصحيح قاعدة CSS كانت تتجاوز ألوان الروابط، والتباين وتسلسل H2/H3. تحسين تسمية السلة، وتمرير العلامات بلوحة المفاتيح، وinert للقائمة المغلقة، وEscape وإدارة التركيز للفروع، ولوحة المفاتيح للخريطة.
- كشف فحص العربية طلب API يحتوي `%25D8...` بسبب ترميز slug مرتين في page render. أُضيف فك ترميز واحد عند قراءة params في صفحات التفاصيل والتصنيفات مع اختبارات انحدار. slugs المخزنة وcanonical لم تتغير.

## التحقق

- `npm ci` و`npm run lint` و`npm run build` بما فيه TypeScript: نجاح. أبلغ npm audit عن 18 تنبيهًا موروثًا؛ لم تُنفّذ ترقيات عشوائية خارج النطاق.
- ثلاثة اختبارات لترميز المسارات: نجاح.
- العربية والإنجليزية، عرض 390 و1440، دون JavaScript: H1 واحد وCTA ونصوص الأقسام مرئية، واتجاه اللغة صحيح.
- Axe للصفحة الرئيسية باللغتين، بما فيه best practice: صفر مخالفات.
- القائمة وEscape، CTA وواتساب، المدن وأرقام التواصل، نافذة الفرع وEscape، reduced motion: نجاح.
- الإضافة للسلة وتغيير الكمية إلى 3 وإرسال quote وإفراغ السلة وحفظ خيارات الخصوصية: نجاح. قائمة منتجات الإنتاج فارغة؛ استُخدم منتج fixture معزول، واعترض المتصفح الإرسال. لم يُنشأ طلب في بيانات الشركة.
- 16 مسارًا فعليًا: الرئيسية والكتالوج والمدونة والمناقصات والسلة وفئة وعلامة ومقال باللغتين. HTTP 200، H1 واحد، metadata وcanonical وJSON-LD سليمة. السلة تحتفظ بـnoindex. قوائم المنتجات والمناقصات الحالية فارغة؛ لا يُدّعى فحص تفاصيل إنتاج غير موجودة. المنتج اختُبر بالـfixture.
- اختبار التسويق يشغّل نفس `src/lib/marketing.ts` بوسائل نقل وهمية: لا SDK قبل الموافقة أو بعد الرفض، تحميل وإرسال الحدث المسموح بعد الموافقة، وتطبيق سحب الموافقة. لم تُرسل أحداث تجريبية لمنصات الإعلان.
- SEO المحلي 69 بسبب `SITE_INDEXABLE=false` الافتراضي الآمن لبيئة الاختبار؛ لم تُغيّر سياسة فهرسة الإنتاج.

## الشبكة وحدود النشر

الاستجابة الفعلية لـHTML على الإنتاج وعلى النسخة المحلية مضغوطة بـgzip. اتصالات موارد الإنتاج استخدمت HTTP/2، و`Alt-Svc` يعلن HTTP/3؛ لم يُثبت استخدام HTTP/3 في الاختبار. ملفات Next ذات hash تحمل cache طويل الأمد immutable. استجابة `_next/image` للصورة القادمة من R2 سليمة بصيغة WebP، مع cache فعلي على المحسّن. ملف R2 الأصلي WebP حجمه 114,124 bytes، و`Cache-Control: public, max-age=31536000, immutable`.

عينة TTFB من جهاز الاختبار إلى settings API نحو 743ms وإلى R2 نحو 1008ms؛ ليست قياسات من VPS. TTFB في جولات الصفحة المحلية تراوح بين 27 و1228ms. المورد المتأخر ليس دليلًا كافيًا لتغيير cache البيانات أو مسار proxy. تفاصيل الاستجابات والـwaterfall في `results.json` وحزمة الأدلة.

اختبار التحريك أكد التبديل على الكمبيوتر والتوقف خارج viewport وعند visibilitychange والتركيز، ثم تعطيله عند تغيير reduced motion. لقطات المقارنة: [قبل](before-mobile.jpg) و[بعد](after-mobile.jpg).

لم تتوفر إدارة Coolify أو نقطة اختبار جغرافية مضبوطة. تبقى إعادة قياس الإنتاج بعد نشر main، وAndroid/4G وINP الميداني، والتحقق من ضغط HTML عند الوكيل العكسي إن أظهرت الاستجابة غيابه. لم يثبت سبب لتغيير صلاحية البيانات أو API. بقي تحويل الجذر 307 إلى `/ar`، وقيس منفصلًا.

## إعادة التشغيل

أدوات الاختبار معزولة عن تبعيات تطبيق الإنتاج. Node 22.18+ أو 24+ لتشغيل اختبارات TypeScript مباشرة:

```powershell
npm install --prefix "$env:TEMP/alwosabe-perf-tools" --no-package-lock playwright lighthouse @axe-core/playwright
$env:PERF_TOOLS_DIR="$env:TEMP/alwosabe-perf-tools"
$env:CHROME_PATH='C:/Program Files/Google/Chrome/Application/chrome.exe'
# اضبط API_URL وNEXT_PUBLIC_API_URL وMEDIA_HOST على إعدادات بيئة الاختبار قبل البناء والتشغيل.
npm ci
npm run lint
npm run build
npm start -- --hostname 127.0.0.1 --port 3100
```

من نافذة أخرى:

```powershell
node --test scripts/performance/route-segment.test.mjs
node scripts/performance/routes.mjs http://127.0.0.1:3100
node scripts/performance/marketing-check.mjs
node scripts/performance/motion.mjs http://127.0.0.1:3100
node scripts/performance/network.mjs http://127.0.0.1:3100
node scripts/performance/audit.mjs http://127.0.0.1:3100 after 3
```

لا تشغّل البناء أو اختبارات متصفح أخرى أثناء Lighthouse. عند خلو الكتالوج، شغّل `fixture-api.mjs` على 4100 ونسخة Next ثانية على 3101 باستخدام `API_URL=http://127.0.0.1:4100`، ثم `regression.mjs http://127.0.0.1:3101`. proxy الاختبار يقبل القراءة فقط ويستبدل بيانات المنتجات؛ quote وSDK معزولة في المتصفح. المخرجات في `artifacts/performance/` أو `PERF_REPORT_DIR`، ولا ترفع إعدادات البيئة.
